# LANXIU Linux 用户手册

面向装机并使用LANXIU Linux 的人：怎么装、怎么装软件、怎么升级、出问题怎么办。

想改配方、加包、改构建系统，请看《维护者手册》。

---

## 1. 安装

### 1.1 需要什么

| 形态 | 最小内存 | 最小磁盘 | 说明 |
|---|---|---|---|
| 桌面 | 4G | 20G | 带图形栈与桌面环境。默认启用声音、网络管理、电源管理与打印。 |
| 最小系统 | 256M | 2G | 只有根目录骨架、init 与基础工具。适合容器镜像、嵌入式设备和作为其他形态的地基。 |
| 移动设备 | 2G | 8G | 安卓设备/手机/平板形态。含触控、电源管理、移动网络与zram。系统分区只读（verified boot 强制），整机走 A/B 槽更新。 |
| 服务器 | 1G | 8G | 最小系统加网络、日志、远程管理。无图形界面，默认开启串口控制台——服务器排查故障靠它。 |
| 开发工作站 | 8G | 40G | 桌面形态加开发工具链。适合本机开发与构建。 |

构建机另算：编译整套系统需要 ≥8 核 / 32G 内存 / 200G 磁盘。

### 1.2 装机

装机分六步，每步可单独重跑——某一步失败不必从头再来：

```bash
# 先生成装机脚本（不直接动磁盘，可以先看一遍脚本再执行）
./bin/qydisk scripts --disk /dev/sda --target /mnt/target \
        --memory 8G --size 100G --profile desktop
```

生成 6 个脚本，按顺序执行，每步可单独重跑：

| 脚本 | 做什么 |
|---|---|
| `1-partition.sh` | 分区（会先二次确认再清空磁盘） |
| `2-mount.sh` | 挂载到 target |
| `3-install.sh` | 按形态装包并做可启动性检查 |
| `4-configure.sh` | chroot 内配置（主机名、locale、用户） |
| `5-bootloader.sh` | 装引导器 |
| `9-umount.sh` | 卸载 |

**先生成脚本而不是直接执行**，是为了让你在运行前能逐行看一遍——
尤其 1-partition.sh，它会清空你指定的整块磁盘。

**清空磁盘前会强制二次确认**——这一步不可逆，脚本会先 wipefs 清掉旧签名。

分区方案是算出来的，不是手填的：swap 跟着内存走（<2G 给 2 倍，
8~64G 给一半上限 8G，>64G 固定 4G）。以下情形会被明确拒绝，
不会让你装到一半才发现：

- 磁盘小于方案所需
- EFI 分区小于 260M（规范下限）
- EFI 分区不是 FAT32
- 同时有两个「自动增长」的分区

### 1.3 为什么 fstab 用 UUID

`root=/dev/sda2` 在加装硬盘、换接口后就指错设备——
「昨天还好好的今天起不来」的头号原因。LANXIU一律写 UUID。

## 2. 装软件

```bash
qypkg install vim git
qypkg remove --unused vim
qypkg search editor
qypkg info vim
qypkg list --installed
```

### 2.1 包格式

自建的 `.qyp` 格式：128 字节头 + JSON 元数据 + tar 数据 + 可分离签名。
**不解压就能校验签名**——仓库索引和包本身都带签名，
任何一环被篡改都会被明确拒绝，不会静默装上。

### 2.2 打了哪些补丁

包元数据里记录了它相对上游打了哪些补丁、为什么打。
你可以查到手上的包和上游源码差在哪，不必猜：

```bash
./bin/qypatch list --package vim
```

补丁和源码一样锁定 sha256——补丁被改会静默改变产物，
那是供应链攻击的入口。

### 2.3 依赖

依赖关系是**自动发现的**：安装时会解析出完整闭包一起装上。
包里的程序链接了哪些共享库，由构建系统扫描产物得出，
不靠维护者手写——手写的必然遗漏。

卸载时会拒绝仍在被依赖的包：

```
qypkg remove openssl
!!! 无法卸载：curl、openssh、python 仍依赖它
```

### 2.4 查文件归属

```bash
qypkg owns /usr/bin/vim      # 这个文件属于哪个包
qypkg why vim                # 谁依赖它（判断能不能删）
```

## 3. 升级

```bash
qypkg upgrade
```

### 3.1 升级是整批事务

一次升级往往横跨几十个包。装到第 30 个失败、前 29 个已写进系统，
断电就是一台半残的机器。LANXIU的做法是**整批事务**：

1. 先做文件级快照
2. 再写入
3. 失败自动全部还原

下次启动还会自动检出上次没完成的事务并回滚——**断电不会留下半升级状态**。

### 3.2 升级前的三项检查

不通过就根本不开始，不会让你升到一半：

- 新依赖是否在仓库里
- 是否与已装包冲突
- 磁盘空间够不够（含快照）

### 3.3 回滚

```bash
qypkg snapshots                    # 看有哪些快照
qypkg rollback 20260930-032946     # 回滚到指定快照
```

快照按事务保留，升级成功后仍可用于回滚。

## 4. 安全更新

```bash
qysec scan --root /                # 这台机器上有什么没修
qysec by-cve --cve CVE-2026-0001   # 某个 CVE 影响哪些包
```

按**版本区间**判定，不是按版本号相等。CVE 影响 1.2~2.0，
只查 `version == 1.2` 会漏掉绝大多数受影响的安装。

扫描输出示例：

```
[critical] libqydemo-0.1.0  CVE-2026-0001 → 修于 0.2.0（可修复）
[critical] qydemo-0.1.0     CVE-2026-0001 → 尚无修复版本（待上游修复）
```

「待上游修复」也会如实报出来，不会假装没问题。

## 5. 可复现构建：你可以自己验证

同一个配方在任何机器上构建，产出的包逐字节相同。
这意味着**你可以自己重编一遍，比对哈希**，
确认官方发布的包里没有夹带任何源码之外的东西。

```bash
export SOURCE_DATE_EPOCH=$(git log -1 --format=%ct)
./bin/qybuild zlib --force
./bin/qyrepro verify zlib    # 连编两次，逐字节比对
```

做不到可复现，这条验证路径就不存在——你只能选择相信。

## 6. 安卓设备

手机/平板/开发板形态（mobile）。引导链与 PC 完全不同：
boot.img 把内核、initramfs、设备树打包成一个文件，
system/vendor 是 super 动态分区里的子分区。

**更新分两层**：整槽更新走 A/B（切槽，失败自动回退），
日常软件更新走包级事务。两套都要有——
只有 A/B 的话，槽内的包升级坏了要等下次整槽更新才能修。

刷机需要解锁 bootloader，**解锁会清空全部用户数据**。

## 7. 出问题怎么办

### 5.1 起不来

GRUB 菜单里**有一个非静默的救援项**——系统起不来时第一件事就是看内核输出。
只给一个 `quiet` 项是给自己找麻烦。

### 5.2 升级后异常

```bash
qypkg snapshots && qypkg rollback <上个快照>
```

### 5.3 装机后权限不对

某些文件系统（virtiofs、容器 overlay）不支持 chmod，
装机脚本会提示「装机到真实磁盘后需复查」。在真实磁盘上不会发生。
